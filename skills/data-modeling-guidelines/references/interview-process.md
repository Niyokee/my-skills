# インタビューの進め方

## 基本姿勢

関係者の回答を収集するだけでなく、具体的な経験から隠れた業務規則を発見する。現在のモデルは質問を選ぶための仮説であり、関係者へ正解を要求する質問票ではない。

一回の対話では、直前の回答から最も影響が大きい未確認事項を一つ選ぶ。質問する理由を短く示し、回答後に理解を要約する。

## 対話記録

次の区分を混ぜない。

| 区分 | 記録内容 |
| --- | --- |
| 確認済みの事実 | 実例、資料、ログ、複数の証言で確認した内容 |
| 合意 | 関係者が将来の規則として選んだ内容 |
| 仮説 | 回答または資料からモデル作成者が導いた内容 |
| 設計判断 | 複数案から選んだ表現または実装方式と理由 |
| 未確認事項 | 確認者、資料、次の質問が必要な内容 |
| 対象外 | 今回は扱わない内容と、扱わない理由 |

## 対話の段階

### 1. 焦点を定める

対象業務全体を一度に聞かない。重要な出来事または利用場面を一つ選ぶ。

最初の質問例は、「直近で実際に起きた一件を、始まりから終わりまで教えてください」です。既存システムの説明から始まった場合は、「システムがなくても業務上は何が起きたと言えますか」と尋ねる。

終了条件は、開始、終了、参加者、主要資料、判断時点が分かることとする。

### 2. 管理対象と出来事を集める

番号、コード、名称、帳票の主題から候補を集める。番号が何を一つに特定するかを確認する。番号がない対象は、現場で何によって同一性を判断するか尋ねる。

質問例は次のとおりである。

- 「この番号は何を一つに特定しますか」
- 「同じ対象の番号が変わることはありますか」
- 「この日付には、何が実際に起きたことが記録されていますか」
- 「予定日、適用日、登録日ではなく、出来事が起きた日はどれですか」

終了条件は、主要候補の識別条件、生成、終了、統合、分割、名称変更が分かることとする。

### 3. 関係と制約を明らかにする

関係を現場の動詞で一文にする。関係の両側から、存在しない場合、ちょうど一つの場合、複数の場合を尋ねる。

質問例は次のとおりである。

- 「AとBの関係を、現場の動詞を使って一文にするとどうなりますか」
- 「一つのAにBがない場合はありますか」
- 「一つのAに複数のBが関わる実例はありますか」
- 「一つのBが複数のAに関わる実例はありますか」
- 「関係が成立する時点と、成立しなくなる時点はいつですか」

「通常は一つ」という回答は最大数の確定ではない。通常と異なる実例、移行中、取り消し、再処理、過去データを追質問する。

### 4. 分類、多値、存在しない値を確かめる

分類値について、重複、漏れ、変更、判定者を尋ねる。複数の値について、独立性、順序、重複、期間を尋ねる。

質問例は次のとおりである。

- 「同時に二つの分類へ属することはありますか」
- 「どの分類にも属さないことはありますか」
- 「複数値は選択肢ですか。それとも全体を構成する明細ですか」
- 「値がない場合は、不存在、未知、未決定、適用外のどれですか」
- 「誰が、どの出来事の後に値を確定しますか」

### 5. 事例で反証する

肯定例だけで合意しない。モデルで表現できない現実と、現実には起こらないがモデルで表現できる状態を探す。

少なくとも、通常例、反例、境界値、取り消し、訂正、同時発生、順序逆転、重複受信、移行前データを確認する。該当しない場合は、その理由を記録する。

### 6. 合意して次へ進む

今回確認した事実、変更した仮説、決めた内容、未確認事項を読み上げる。次の対話で最も重要な一問を決める。

対象範囲の終了条件は、重要な未確認事項が解決済みであるか、未解決の影響と確認責任者が合意されていることである。

## 対話が停滞した場合

- 抽象論が続く場合は、直近の実例へ戻る。
- 回答が対立する場合は、両方を仮説として残し、適用条件が異なる具体例を探す。
- 詳細を覚えていない場合は、原帳票、ログ、コード表、問い合わせ記録の確認へ切り替える。
- 解決策の話だけになる場合は、その解決策が存在しないときに困る人、困る出来事、守る規則を尋ねる。
- 用語が揺れる場合は、用語表をその場で更新し、同一対象か別対象か確認する。
