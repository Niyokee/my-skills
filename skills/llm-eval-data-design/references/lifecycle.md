# 評価データの版管理と継続更新

## 管理する対象

次を別々に版管理する。

- 評価データ
- アプリケーション
- システム指示とプロンプト
- 基盤モデルと生成設定
- 検索対象と検索処理
- 利用可能なツールと権限
- 参照解と採点基準
- 採点器

評価結果には、実行した各版を記録する。評価方法を変更した場合は、変更前後の値を同じ尺度として扱わない。

## リリース前

- 製品要件、手動試験、専門家作成例、合成例から能力・リスク評価集合を作る。
- 中核フローと確認済みの失敗から回帰評価集合を作る。
- 代表性評価集合を作る場合は、配分が想定分布であることを明記する。
- 開発用集合と最終判定用集合を分ける。
- 本番後に収集するログ項目と、利用者データの取り扱い条件を決める。

## リリース後

Anthropicは、本番監視を、分布変化と事前評価で想定しなかった現実の失敗を検出する手段として位置づけている。[^anthropic-evals] OpenAIは、リリース後の実トラフィックで同じ測定を行い、リリース前の予測を検証する方法を説明している。[^openai-deployment]

次のデータを評価候補として収集する。

- 本番トラフィックから確率的に抽出した事例
- 利用者の低評価と苦情
- 異常な処理時間または費用
- ツール、検索、外部依存先の失敗
- 人間による手動介入と引き継ぎ
- 安全性または品質上のインシデント
- 新しい利用目的、言語、入力形式

## 評価集合への追加規則

### 回帰評価集合へ追加する

次の条件をすべて満たす失敗を追加する。

1. 失敗を再現できる。
2. 期待する挙動を定義できる。
3. 失敗分類と原因の範囲を記録できる。
4. 修正後の合否を判定できる。

個人情報や機密情報を含む場合は、保存条件に従って匿名化、置換、アクセス制限を行う。変換後も、失敗を引き起こした条件が保持されているか確認する。

### 代表性評価集合へ追加する

- 対象期間と母集団を定義する。
- 抽出方法と抽出確率を記録する。
- 層別抽出した場合は、母集団比率と集計用の重みを記録する。
- 同一利用者または同一会話に由来する複数事例を識別する。
- 合成データと本番由来データを区別する。

## 更新の契機

- 利用者または利用目的が変わった。
- 新しい言語または入力形式を追加した。
- モデル、検索、ツール、権限を変更した。
- 新しい失敗分類が見つかった。
- 層別の成功率または入力比率が変化した。
- 参照解または採点基準を変更した。
- 採点器と人間の不一致が増えた。

OpenAIは、評価を一度限りで終わらせず、変更ごとに継続して実行するよう勧めている。[^openai-best-practices]

## 比較可能性を保つ

- 評価データを追加または削除した場合は、集合の版を変える。
- 同じ版の集合に対する結果と、更新後の集合に対する結果を分ける。
- 採点基準を変更した場合は、必要に応じて過去の出力を新基準で再採点する。
- モデルの複数試行を行う場合は、試行数と集約方法を固定する。
- 本番分布の変化と、アプリケーション性能の変化を区別する。

## 定期レビューの出力

- 各評価集合の版と件数
- データの由来別の件数
- 層別の入力比率と成功率
- 新しく追加した失敗分類
- 回帰評価の新規失敗
- 採点器と人間の不一致
- 本番分布とリリース前の想定分布との差
- 次回更新までに確認する仮説
