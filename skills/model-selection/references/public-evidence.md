# 公開情報とベンチマークの扱い

## 目的

公開情報を使って候補を効率よく絞り込みながら、用途との不一致、集計方法、再現性、データ汚染による誤判断を避ける。

## 情報源の優先順位

具体的なモデルを比較する場合は、現在の情報を次の順で確認する。

1. モデル提供者のモデルカード、技術報告、公式文書
2. 公式の料金表、利用規約、廃止予定、提供地域
3. ベンチマークの原論文、公式データ、公式の評価コード
4. 評価条件を開示した独立した第三者の再現結果
5. ランキング、記事、利用者の報告

下位の情報源だけで重要な判断を確定しない。各情報について、確認日、モデルの完全な版、提供事業者、評価条件を記録する。同じ名称でも版や提供方式が異なる結果を混ぜない。

## ベンチマークの適合性

公開得点を使う前に、次の事項を確認する。

- 測定している能力が対象タスクに必要か。
- 自由形式の生成が必要なのに、多肢選択だけを測っていないか。
- 入力言語、領域、長さ、モダリティが実運用に近いか。
- 指標が利用者にとって重要な失敗を区別できるか。
- 評価時のプロンプト、例示、生成設定、外部ツールが開示されているか。
- 上位モデルの得点が上限に近づき、差を区別できなくなっていないか。

適合しないベンチマークは、広い能力の参考値として扱う。用途固有の性能を示す根拠にはしない。

## ランキングと集計

ランキングを使う場合は、含まれるベンチマークと集計方法を確認する。単純平均には、異なる難易度、単位、用途上の重要度を同じものとして扱う問題がある。

複数のベンチマークが同じ能力を測っている場合、強く相関した得点を重ねることで、その能力の影響が過大になる。用途に必要な能力の範囲を先に定め、重複するベンチマークを減らす。

独自の集計値を作る場合は、次の内容を開示する。

- 採用したベンチマークと除外したベンチマーク
- 各ベンチマークが表す評価基準
- 正規化方法、重み、欠損値の扱い
- 重みを変えた場合の順位変化

集計前の各得点も残す。総合順位だけで候補の弱点を隠さない。

## データ汚染

データ汚染とは、評価データまたは実質的に同じ内容がモデルの学習に使われ、暗記によって得点が高くなる状態を指す。公開時期が学習期間より前であるだけでは、汚染を証明できないが、可能性を高める。

次の情報を確認する。

- 学習データの期間と開示範囲
- 評価データとの文字列または意味上の重複
- 評価データに対する不自然に低いパープレキシティ
- 提供者が報告する汚染率と、汚染除去後の得点
- 問題文の言い換えや新しい非公開問題で性能が維持されるか

学習データへアクセスできない場合、汚染していないと断定しない。公開ベンチマークの得点は候補の絞り込みに限定し、最終比較には非公開の用途固有データを使う。

## 公開情報から候補を絞る手順

1. 必須条件を満たすモデルだけを一覧にする。
2. 用途に対応する公開評価を選ぶ。
3. 評価条件とモデルの版をそろえる。
4. 品質、価格、レイテンシ、必要機能の明らかな劣後候補を除外する。
5. 根拠の確かさと不足情報を候補ごとに記録する。
6. 用途固有の比較実験へ進める少数の候補を残す。

公開情報が存在しないことを低性能の証拠として扱わない。重要な候補に値がない場合は、同じ条件で自ら測定する計画を立てる。

## 証拠表

候補ごとに次の内容を記録する。

| 項目 | 記録する内容 |
| --- | --- |
| 候補 | モデル、版、提供事業者、実行方式 |
| 主張 | 比較に使う性能、価格、機能、制約 |
| 値 | 単位と集計範囲を含む公開値 |
| 条件 | データ、プロンプト、生成設定、ハードウェア |
| 情報源 | 主張を直接裏付ける文書 |
| 確認日 | 情報を確認した日付 |
| 確かさ | 確認済み、条件付き、未確認のいずれか |

異なる条件で測定された値を横並びにする場合は、直接比較できないことを明記する。
