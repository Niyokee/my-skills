# 型の臭いから問題を特定する

既存コードをレビューするとき、症状から問題と参照先を引くための索引である。

各スキルの「レビュー項目」は、確認すべき問いの一覧である。この文書は逆向きに、
コード上で目に見える徴候から、疑うべき業務規則違反を特定する。

## 使い方

1. 対象の型定義と関数シグネチャを読み、下表の徴候と照合する。
2. 該当した項目の参照先を読み、業務規則を確認する。
3. 指摘は多くても6件に絞る。効果の大きい順に並べる。

## 単一値の徴候

| 記号 | 徴候 | 発生できる不正状態 | 参照 |
| --- | --- | --- | --- |
| V-1 | 業務上意味を持つ値が`string`または`number`のまま | 引数の順序違いが型検査を通る。`customerId`と`orderId`を交換できる | [integrity.md](integrity.md) |
| V-2 | 数値に単位が現れていない（`timeout`、`amount`、`quantity`） | 秒とミリ秒、個数と重量を交換できる | [integrity.md](integrity.md) |
| V-3 | 日時にタイムゾーンの区別がない | UTCとローカル時刻を交換できる | [integrity.md](integrity.md) |
| V-4 | 文字列に長さ、改行可否、正規化規則が定義されていない | 保存先の桁数を超える値がドメインを通過する | [integrity.md](integrity.md) |
| V-5 | 公開コンストラクタと検証関数が併存している | 検証を通らない値を生成できる | [integrity.md](integrity.md) |
| V-6 | 永続化層または表示層で長さを切り詰めている | 判断すべきでない層が切り詰めか例外かを決めている | [integrity.md](integrity.md) |
| V-7 | 呼び出し側が独自の検証を書いてからドメインへ渡している | 検証規則が二重化し、いずれ乖離する | [integrity.md](integrity.md) |

## 状態の徴候

| 記号 | 徴候 | 発生できる不正状態 | 参照 |
| --- | --- | --- | --- |
| S-1 | 省略可能なフィールドを並べて「いずれか必須」を表している | すべて存在しない状態を作れる | [states.md](states.md) |
| S-2 | 省略可能なフィールドが3つ以上並んでいる | 業務上ありえない組み合わせを作れる。暗黙の状態機械である | [states.md](states.md) |
| S-3 | 真偽値のフラグ（`isVerified`、`isPaid`、`isApproved`） | 状態に固有のデータを持てず、S-2へ退化する | [states.md](states.md) |
| S-4 | 状態を表す列挙と、それに依存するフィールドが同じ型にある | 状態と付随データが矛盾する組み合わせを作れる。列挙に値を追加しても既存の分岐が壊れない | [states.md](states.md) |
| S-5 | 省略可能な値の有無で状態を判定している | 値の不在と状態の判別が混在する | [states.md](states.md) |
| S-6 | 分岐の最後が「残りすべて」を前提にしている | 状態を追加したとき誤った既定動作が続く | [states.md](states.md) |
| S-7 | 「検証済み」「承認済み」を真偽値またはコメントで表している | 処理を経ずに後続状態を生成できる | [states.md](states.md) |
| S-8 | 同じ役割のコレクションが並列に並んでいる | 追加した要素を処理し忘れても型検査を通る。未命名の概念が隠れている | [states.md](states.md) |
| S-9 | 「最低1件」の規則があるのに通常のコレクション型 | 空の状態を作れる | [aggrigate.md](aggrigate.md) |

## 関数シグネチャの徴候

シグネチャを読むだけで挙動を予測できるかが判定の基準である。

| 記号 | 徴候 | 発生できる不正状態 | 参照 |
| --- | --- | --- | --- |
| F-1 | 失敗し得るのに戻り値の型が成功だけを表している | 呼び出し側が失敗の処理を書かなくても型検査を通る | [usecase.md](usecase.md) |
| F-2 | 同期的な見た目の関数が内部で入出力を行う | 実行時間と失敗の可能性が予測できない。テストに外部環境が必要になる | [usecase.md](usecase.md) |
| F-3 | 現在時刻、乱数、グローバル値を関数内部で取得している | 同じ入力に対して結果が変わる。差し替えられない | [usecase.md](usecase.md) |
| F-4 | ドメインの関数が`void`を返し、引数を直接変更している | 何が変わったかを型が示さない。共有された参照が別経路から書き換わる | [identity.md](identity.md) |
| F-5 | ユースケースの入力が可変オブジェクト、戻り値が真偽値または`void` | 必要な入力と保証される結果が型から読めない | [usecase.md](usecase.md) |
| F-6 | 複数の処理段階が同じ型を受け取り同じ型を返している | 検証前の値を検証後の処理へ渡せる。処理順序が守られない | [states.md](states.md) |
| F-7 | エラーが文字列または汎用の例外型 | 呼び出し側が種類で分岐できない。種類を追加しても既存コードが壊れない | [usecase.md](usecase.md) |
| F-8 | 業務上の失敗と技術的な失敗が同じ型に並んでいる | 扱いと公開範囲が異なる失敗を同じ粒度で処理させる | [usecase.md](usecase.md) |
| F-9 | ユースケースの出力が固定のオブジェクト型 | 結果を追加するたびに呼び出し側が壊れる | [usecase.md](usecase.md) |

## 集約と境界の徴候

| 記号 | 徴候 | 発生できる不正状態 | 参照 |
| --- | --- | --- | --- |
| A-1 | 導出できる値を保持し、元データと別経路で更新できる | 合計と明細が一致しない状態を作れる | [aggrigate.md](aggrigate.md) |
| A-2 | 集約の子要素を単独で更新する関数が公開されている | 集約ルートを通さず不変条件を破れる | [aggrigate.md](aggrigate.md) |
| A-3 | 同じ制約の検証処理が複数の集約に重複している | 一方だけ規則が変更され、規則が分岐する | [aggrigate.md](aggrigate.md) |
| A-4 | 他の集約のデータが写しとして埋め込まれている | 元が変わっても追随せず、どちらが正か型から読めない | [aggrigate.md](aggrigate.md) |
| A-5 | ドメイン型に直列化の属性や永続化基盤の型が現れている | 通信形式と保存形式の都合がドメインモデルを歪める | `design-guidelines` |
| A-6 | ドメインの計算処理の途中で永続化層を呼んでいる | ドメインの検証に外部環境が必要になる | `design-guidelines` |

A-5とA-6は、ドメインと外部との境界の論点である。参照先は別のスキルに属するため、
`design-guidelines`の`references/boundary-io.md`を読む。

A-4は、意図的な写しであれば残してよい。判定は「元が変わったとき追随すべきか」である。
追随すべきなら識別子で参照する。追随すべきでないなら、その時点の値であることを
名前で示す（`billingAddressAtOrderTime`）。この問いに答えないまま埋め込んでいる状態が問題である。

## 型だけでは保証できない範囲

この索引は、型定義とシグネチャから読み取れる徴候だけを扱う。
実行時の競合、メッセージの消失、期限内の収束は判定できない。
それらは`design-guidelines`で扱う。
