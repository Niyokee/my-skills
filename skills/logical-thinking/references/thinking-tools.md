# 情報を整理する技術

この文書は、MECE、グルーピング、観察・洞察のSo What?／Why So?を使って、素材を課題に答えるメッセージへ整理するための判断基準を定める。

## 1. MECEを判定する前に対象全体を定める

MECEは、Mutually Exclusive and Collectively Exhaustiveの略称である。この文書では、同じ階層の要素に大きな重複がなく、課題に必要な範囲に大きな漏れがない状態を指す。

MECEかどうかは、対象全体と分類の目的がなければ判定できない。最初に次を明記する。

- 何を分類するか
- どの範囲を全体とみなすか
- 何を判断または実行するための分類か
- どの時点、地域、組織、利用者を対象にするか

すべての可能性を列挙できない場合は、「現在確認できた選択肢」などと範囲を限定する。根拠なく「網羅的」と表現しない。

## 2. 一つの階層では一つの分類軸を使う

同じ階層には、同じ問いへの答えを並べる。たとえば、顧客を分類する階層に、顧客の属性と販売経路を混在させない。

分類した後は、次を確認する。

- 各要素の定義が重なっていないか。
- どの要素にも属さない事例がないか。
- 課題と関係しない要素が混ざっていないか。
- 要素の粒度がそろっているか。
- グループ名が中身の共通点を正確に表しているか。

既知の枠組みは、分類軸を考える手掛かりとして使う。課題や対象全体に合わない枠組みを、網羅性の根拠として機械的に当てはめない。

## 3. グループ名をメッセージにする

「市場」「課題」「その他」のような名詞だけでは、そのグループから何が言えるか分からない。グループ名は、可能な限り主語と述語を持つメッセージにする。

自作例:

- 弱い見出し: `顧客`
- メッセージ: `既存顧客の継続率が低下している`

メッセージにできない場合は、グループ内の要素が同じ意味を支えているかを再確認する。

## 4. So What?／Why So?の共通原則

So What?は、素材全体またはグループから、課題に照らして結局何が言えるかを抽出する問いである。Why So?は、抽出したメッセージに対して、なぜそう言えるのか、具体的に何を指すのかを問い、素材との対応を検証する問いである。

So What?だけで先へ進まない。得たメッセージへWhy So?を問い、素材へ戻れることを確認する。Why So?で戻れない場合は、素材の追加だけでなく、メッセージの範囲または確実性を弱めることも検討する。

## 5. 観察のSo What?を行う

観察のSo What?は、提示された事象や事実を全体集合として扱い、その要点を正確に要約する。素材とは異なる種類の情報を新たに導かない。

次の順で行う。

1. 課題と観察対象を確認する。
2. 数値、比較対象、期間、条件をそろえる。
3. 共通点、相違点、変化、偏り、例外を特定する。
4. 課題に関係する特徴を、素材の範囲を越えない一文にまとめる。
5. 素材の一部を都合よく除外していないか確認する。

観察のメッセージには、素材が示していない原因、評価、将来予測、取るべき行動を混ぜない。

## 6. 観察のWhy So?を行う

観察のWhy So?は、要約した観察結果を元の事象や事実へ要素分解し、要約が素材全体に対応しているかを検証する。

次を確認する。

- 要約中の各語を、具体的な事実または数値で説明できるか。
- 比較や変化の基準時点が明確か。
- 例外が要約を覆さないか。
- 要約から元の主要な事実を復元できるか。
- 要約が素材より強い断定になっていないか。

元の主要な事実を復元できない場合は、要約が抽象的すぎる。要約に対応しない事実が残る場合は、漏れまたはずれを確認する。

## 7. 洞察のSo What?を行う

洞察のSo What?は、観察した特徴を踏まえ、課題に対する規則性、背景、影響、判断、または取るべき行動を導く。観察とは異なる種類の情報を導くため、推論を伴う。

次の順で行う。

1. 観察のSo What?で得た特徴を並べる。
2. 特徴の共通項、相互関係、背景、因果関係の候補を探す。
3. 課題と相手に期待する反応に照らして、意味のある示唆を選ぶ。
4. 事実から示唆へ進む判断基準、因果関係、または前提を明記する。
5. 示唆を、判断または行動へつながる一文にする。

「重要である」「対応を強化する」など、対象や変化が分からない表現で済ませない。観察だけで確定できない内容は仮説と明記する。

## 8. 洞察のWhy So?を行う

洞察のWhy So?は、導いた規則性、影響、判断、または行動が、観察した事実と推論過程によって支えられるかを検証する。

次を分けて示す。

1. 根拠となる観察結果
2. 観察結果から洞察へ進む判断基準、因果関係、または前提
3. 導いた洞察

次の場合は話が飛んでいる。

- 洞察を支える観察結果がない。
- 相関だけを根拠に因果関係を断定している。
- 暗黙の判断基準を置かないと洞察へ進めない。
- 一つの事例から対象全体を断定している。
- 可能性を示す素材から確定的な洞察を出している。
- 他の有力な説明や反例を検討していない。

洞察を確定できない場合は、仮説、追加確認事項、確定後に変わる判断を示す。

## 9. 観察と洞察を順に往復する

原則として、次の四段階を順に行う。

```text
事象・事実
  └─ 観察のSo What? ── 観察結果
       └─ 観察のWhy So? ── 事象・事実へ戻って検証
            └─ 洞察のSo What? ── 意味・判断・行動
                 └─ 洞察のWhy So? ── 観察結果と推論へ戻って検証
```

観察の検証が終わる前に洞察へ進むと、誤読した事実を前提に判断する危険がある。洞察から元の事実まで戻るときは、洞察のWhy So?で推論を確認した後、観察のWhy So?で事実との対応を確認する。

## 10. 方法は実行可能な具体性まで確認する

提案の方法が、対象や時点を変えてもそのまま通用する一般論であれば、今回の課題を解く方法としては具体性が不足している。

次を確認する。

- 誰が何をするか。
- 何を対象にするか。
- いつまでに行うか。
- 現状から何を変えるか。
- 実行できたかを何で判断するか。

「抜本的に」「十分に」「全社一丸で」などの修飾語を追加しても、方法の具体性は高まらない。

## 整理時の確認項目

- 対象全体と分類の目的を定義したか。
- 同じ階層で分類軸を混在させていないか。
- 大きな重複、漏れ、課題からのずれがないか。
- グループ名が中身の意味を表すメッセージになっているか。
- 観察のSo What?が素材の要約にとどまっているか。
- 観察のWhy So?で元の事実へ分解して戻れるか。
- 洞察のSo What?で課題に対する意味、判断、または行動を導いたか。
- 洞察のWhy So?で観察結果と推論過程へ戻れるか。
- 観察、洞察、仮説を区別したか。
- 方法が今回の対象と状況に固有の内容になっているか。
