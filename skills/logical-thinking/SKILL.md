# Logical Thinking

## 目的

照屋華子・岡田恵子『ロジカル・シンキング』で扱われる考え方に沿って、相手が余計な推測をしなくても理解し、判断し、行動できる論理構造を作る。情報を分類するだけで終わらせず、課題に答えるメッセージへまとめ、結論と根拠のつながりを検証する。

## 基本方針

- 最初に、今回答える課題と、相手に期待する反応を定める。
- MECEは目的ではなく、課題に必要な範囲の重複、漏れ、ずれを点検するために使う。
- 観察のSo What?／Why So?で事実の要点を確定してから、洞察のSo What?／Why So?で意味、判断、行動を導いて検証する。
- 「なぜそう言えるか」を支える根拠と、「なぜそうなるか」を説明する仕組みまたは因果を区別する。
- 根拠または方法という役割と、並列型または解説型という構成方法を分けて選ぶ。
- 一つの課題を深く展開する縦の組み合わせと、二つの課題への答えを並べる横の組み合わせを区別する。
- 結論と根拠の縦の関係だけでなく、同じ階層に並ぶ要素の横の関係も確認する。
- 入力にない事実を補って論理を成立させない。不足情報、仮定、推論を区別する。
- レビューだけを求められた場合は、対象を変更せず、問題の根拠と最小限の改善案を示す。

## 作業手順

### 1. コミュニケーションの前提を定める

次の項目を入力から特定する。不明な項目が結果を大きく変える場合は確認する。作業を進められる場合は仮定を明記する。

- 課題: 今回、答える問いまたは扱うテーマ
- 相手: 誰が受け取るか
- 相手の前提知識: 相手が知らない用語、略号、データ構造、仕組み、比較条件
- 期待する反応: 理解、判断、助言、承認、実行のどれを求めるか
- 対象範囲: 何を含み、何を含めないか
- 制約: 期限、費用、方針、利用できる情報

### 2. 素材をメッセージ単位に分ける

入力を、主語と述語が分かる短いメッセージに分ける。事実、判断基準、判断、提案、方法、仮定、未確認事項を区別する。課題との関係を説明できないメッセージは、ずれの候補として分離する。

### 3. 前提の解説を作る

論理ツリーで使う用語、略号、データ構造、対象そのものの仕組み、比較条件を洗い出す。相手が知らない内容を前提として、課題への答えの後、論理ツリーの詳細より先に読める短い解説にする。ここで扱う仕組みは、用語や対象を理解するための定義に限る。観察した結果が生じた理由を説明する因果関係は、確認済みか仮説かを示し、その観察の下に置く。

前提の解説は結論の根拠ではないため、論理ツリーの外に置く。論理ツリーから必要な場合は「前提1による」のように参照する。略号や識別子をメッセージの主語にせず、初出で正式名称を示してから括弧内に略号または識別子を添える。

前提の解説を作り終えたら、各文へ「これは対象の定義か、観察した結果の理由か」と問う。観察した結果の理由である文は前提の解説へ残さず、次の形で論理ツリー内の該当する観察の下へ移す。

```text
観察: 確認できた結果
└── 理由（確認済み）または理由（仮説）: 結果が生じた説明
```

### 4. 情報を整理する

課題に合う分類軸を明示してグルーピングする。各グループと同じ階層の要素について、重複、漏れ、ずれを点検する。分類軸や対象全体を定義できない場合は、MECEと断定せず、確認できた範囲を示す。

### 5. 観察と洞察を分けてSo What?／Why So?を往復する

最初に観察のSo What?で事実の要点をまとめ、観察のWhy So?で元の事実へ分解して戻れるか確認する。次に洞察のSo What?で、課題に対する意味、判断、または行動を導く。洞察のWhy So?で、観察した事実と推論過程が洞察を支えるか確認する。根拠が足りない場合は、洞察を仮説として示すか、結論の範囲と確実性を弱める。

### 6. 課題の数と答えの役割を定める

課題を、一つの問いとして答えるか、二つの問いへ分けて答えるかを決める。各課題について、答えが結論の妥当性を示す根拠なのか、結論を実行する方法なのかを定める。二つの課題が「何をすべきか」と「どのように実行するか」である場合は、前者を根拠の論理、後者を方法の論理として別々に作る。

### 7. 並列型と解説型を組み合わせる

全体像をMECEに示す場合は並列型を使う。事実、判断基準、判断内容を示して結論または方法の選択過程を説明する場合は解説型を使う。一つの課題を下位階層へ展開する場合は、各要素の下に必要な型を縦に組み合わせる。二つの課題に答える場合は、根拠と方法について選んだ型を横に組み合わせる。

### 8. 縦と横から検証する

- 各階層について、その階層が答える問いと、要素を並べる分類軸を記録する。
- 分類軸の各区分と、直下に置いた各要素が一対一で対応するか確認する。
- 下位の要素から上位の結論を言えるか、So What?で確認する。
- 上位の結論を下位の要素が支えているか、Why So?で確認する。
- 結論の直下にある要素が「なぜそう言えるか」への答えであり、「なぜそうなるか」という仕組みの説明になっていないか確認する。
- 観察した結果の理由を示す説明または仮説が、前提の解説ではなく、それが説明する観察の下に置かれているか確認する。
- 同じ階層の要素が同じ種類と粒度で並んでいるか確認する。
- 同じ階層の要素に大きな重複、漏れ、課題からのずれがないか確認する。
- 主張をつなぐ判断基準、因果関係、前提が省略されていないか確認する。
- 各メッセージが、入力中の事実、明示した前提、または示した推論過程のどこへ戻るか確認する。

### 9. 結果を提示する

最初に課題への答えを一文で示す。その後に論理構造、根拠、指摘、改善案を示す。元の資料にない内容を補う場合は、提案または仮定と明記する。

## 整理結果の形式

新しい論理構造を作る依頼では、原則として次の順で提示する。

1. 課題
2. 相手に期待する反応
3. 答え
4. 相手の前提知識と前提の解説。対象の定義だけを置き、観察した結果の理由または因果仮説を置かない
5. 課題ごとの答えの役割: 根拠または方法
6. 選んだ論理パターンと選択理由
7. 論理構造。各階層の見出しに「この階層が答える問い」と「分類軸」を添える。結果の理由を扱う場合は、対応する観察の直下に「理由（確認済み）」または「理由（仮説）」として置く
8. 検証。階層ごとのSo What?／Why So?の成立、MECE、分類軸と直下要素の対応、説明または仮説とそれが説明する観察の対応、出典へ戻れないメッセージの有無を示す。該当がなくても「なし」と記載する
9. 不足情報と仮定

論理構造は、見出しの階層または入れ子の箇条書きで示す。各階層では、結論、根拠、方法、事実、判断基準、判断のどれであるかが判別できる表現を使う。依頼が整理だけの場合は、求められていないレビュー結果を追加しない。

出力直前に、前提の解説にある各文を「対象の定義」「比較条件」「観察した結果の理由」のいずれかへ分類する。「観察した結果の理由」が一文でも残っている場合は未完了とし、その文を論理構造内の対応する観察の下へ移してから出力する。

## レビュー結果の形式

最初に、課題へ答えられているかと、最も重大な論理上の問題を要約する。各指摘には次の内容を含める。

- 問題の種類: 重複、漏れ、ずれ、話の飛び、前提不足、根拠と説明の混同、分類軸の混在、粒度の不一致
- 根拠: 対象中の該当する記述または構造
- 影響: 相手が理解、判断、行動するときに起こる問題
- 最小限の改善案: 削除、統合、追加確認、順序変更、結論の限定のいずれか
- 改善後も残る範囲: 入力不足や外部確認が必要な点

問題がない項目を水増しして列挙しない。指摘の重要度が異なる場合は、課題への回答を妨げる問題から順に示す。

## 別の媒体へ移す

論理構造を文書、スライド、ウェブページなどへ移す場合は、次の順序を保つ。

1. 課題と答え
2. 前提の解説
3. 論理ツリーの全体図
4. 論理ツリーの枝ごとの説明
5. 判断基準と判断内容
6. 事実、推論、仮説の確かさ

一つのページ、スライド、または節には一つのメッセージを置き、そのメッセージを見出しにする。観察と、観察が生じた理由の説明または仮説は、同じ単位へ置く場合でも「観察」「理由（確認済み）」または「理由（仮説）」という別の領域に分け、同じ箇条書きへ混在させない。理由だけを前提説明のページ、スライド、または節へ移さない。

媒体に合わせて情報を短縮しても、階層ごとの問い、分類軸、親子関係、前提への参照、出典への対応を変えない。移し終えた後に、元の論理構造と移した成果物をメッセージ単位で照合する。

移す前に、次の六つの要素と移行先のページ、スライド、または節を対応づける。移行先の枚数または節数が少ない場合は、隣接する要素を一つの単位へまとめてもよい。ただし、同じ単位の中で領域と見出しを分け、どの要素も省略しない。元の論理構造に全体図がある場合は、全体図を省略しない。全体図は、課題、答え、主要な枝の親子関係が一目で追えるツリーまたは同等の図とする。枝の要約を順不同の箇条書きにしただけのものは、全体図とみなさない。

| 元の論理構造の要素 | 移行先 |
| --- | --- |
| 課題と答え | ページ、スライド、または節を記載 |
| 前提の解説 | ページ、スライド、または節を記載 |
| 論理ツリーの全体図 | ページ、スライド、または節を記載 |
| 論理ツリーの枝ごとの説明 | ページ、スライド、または節を記載 |
| 判断基準と判断内容 | ページ、スライド、または節を記載 |
| 事実、推論、仮説の確かさ | ページ、スライド、または節を記載 |

## 完了条件

- 課題、相手、期待する反応が明示されている。
- 相手が知らない前提が洗い出され、論理ツリーの外で説明されている。
- 前提の解説に、観察した結果の理由または因果仮説が混入していない。
- 結論が課題に直接答えている。
- 各結論について、入力中の根拠へ戻れる。
- 各メッセージが、入力、明示した前提、または推論過程のどこへ戻るか確認されている。
- 出典へ戻れないメッセージは削除されるか、仮説または提案として明示されている。
- 観察のSo What?／Why So?と洞察のSo What?／Why So?が区別されている。
- 根拠と、仕組みまたは因果の説明が混同されていない。
- 観察した結果の理由を示す説明または仮説が、それが説明する観察の下に置かれている。
- 課題ごとに、根拠または方法という答えの役割が明示されている。
- 並列型または解説型を選んだ理由が、相手に期待する反応と対応している。
- 一つの課題では縦の展開、二つの課題では課題ごとの構造と横の組み合わせが示されている。
- 各階層が答える問いと分類軸が出力に明記されている。
- 各直下要素が、明記した分類軸のいずれか一つに対応している。
- 同じ階層の分類軸と粒度がそろっている。
- 重複、漏れ、ずれ、話の飛びの確認結果が示されている。
- 事実、判断基準、判断、仮定、未確認事項が混同されていない。
- レビューの場合は、指摘と最小限の改善案が対応している。
- 別の媒体へ移した場合は、移行対応表の全項目に移行先があり、全体図が親子関係を示し、元の論理構造と移した成果物がメッセージ単位で一致している。
